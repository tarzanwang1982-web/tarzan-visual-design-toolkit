# Mermaid Diagrams
Use for flowcharts, sequence diagrams, state diagrams, architecture/system relationships, timelines, journeys, class/entity relationships, and other structured visual explanations.

Upstream: https://github.com/mermaid-js/mermaid

## Workflow
1. Decide the diagram type from the information relationship.
2. Reduce content to nodes, actors, states, events, or relationships.
3. Write the simplest valid Mermaid definition.
4. Use short labels and a clear reading direction.
5. Add styling only after structure is understandable.

## Rules
- Do not force complex prose into one giant diagram.
- Split diagrams when they have competing narratives.
- Keep source editable.
- Verify current Mermaid syntax and supported diagram types upstream before relying on newer features.

Combine with Simple Icons for architecture explanations when brand/service recognition helps.
